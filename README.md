# PropHandoff

Blender add-on (4.2 → 5.x) to animate **props held by a character** — handing a
sword from one hand to the other, gripping a spear with both hands, throwing a
ball — without building constraints and keyframes by hand.

Everything the add-on creates is native Blender data (constraints, empties,
drivers, custom properties). It is saved in the `.blend` and survives a restart,
even with the add-on disabled. Every driver expression is a *simple expression*:
*Auto Run Python Scripts* is never needed.

---

## What it does

**Transfers — the prop follows a hand.**
Pick the prop, *Setup Prop*, then at the right frame *Assign → Left hand*. The
prop does not move by a pixel, it is now attached. Later: the other hand,
*Release* in world space, or *Throw* along a parabola that extends the gesture.
The transfer history is rebuilt from the F-Curves and is navigable
(*Previous / Next / Go*).

**Two-Hand Grip — the hands follow the prop.**
For a long object: *Grip Zone* (the free hand catches the shaft by proximity,
driver-based, no dependency cycle), keyframed *Attach* of both hands, *Master
Hand* (the prop follows one hand, the other hand follows the prop), and an arm
reach limit so the character cannot stretch past its own arms.

**Several props at once.** A knife in one hand and a katana in the other: each
object has its own slots, constraints and history. Every configured object shows
up as a tab in the panel, switchable in any mode.

## Install

1. Download `prop_handoff_v<X.Y.Z>.zip` from the
   [Releases](../../releases) page.
2. Blender → *Edit ▸ Preferences ▸ Add-ons ▸ ▾ ▸ Install from Disk…* → pick the
   zip, tick **PropHandoff**.
3. The **PropHandoff** tab appears in the sidebar (`N`) of the 3D View.

Updating: disable, *Remove*, **restart Blender** (the modules stay in memory),
then install the new zip.

`prop_handoff_extension.zip` in the same release is the same add-on packaged for
the [Blender Extensions](https://extensions.blender.org) platform (manifest
instead of `bl_info`). Install one or the other, never both at once.

## Supported rigs

Developed and tested in **Blender 5.2** on an **Auto-Rig Pro** rig
(`c_hand_ik.l` / `c_hand_ik.r`) and on a **Rigify** human generated by the
Rigify bundled with Blender (`hand_ik.L` / `hand_ik.R`), arms in IK. Any rig
whose hands are driven by IK controllers should work; rigs with FK-only arms are
supported for transfers (section 1) only.

## Feedback

Bug reports and rig-compatibility reports are very welcome — please open an
[issue](../../issues) with your Blender version, the rig you use (Auto-Rig Pro,
Rigify, custom) and what you did, frame by frame, before the problem appeared.

## Tests

```
powershell -File tests/run_headless.ps1                        # synthetic scene
powershell -File tests/run_rig_protocol.ps1 -Rigify            # generated Rigify rig
powershell -File tests/run_rig_protocol.ps1 -Blend <file.blend>  # your own rig
```

The first suite builds its own scene and checks the whole API; the second replays
the animation protocol on a real rig and compares against the specification.
